# 站点使用与维护说明

本文档说明这个博客的日常维护方式：如何新建和删除文章、如何调整导航目录、如何修改站点名称、如何更换图片，以及发布流程和常见问题。

所有内容都在 `docs/` 目录下，站点配置集中在根目录的 `mkdocs.yml` 中。

---

## 1. 目录结构

```text
My-Blog/
├── docs/                      # 站点内容
│   ├── index.md               # 首页（中文）
│   ├── index.en.md            # 首页（英文）
│   ├── about.md               # 关于页
│   ├── about.en.md
│   ├── 使用说明.md             # 本文档
│   ├── posts/                 # 个人文章
│   │   ├── hello-world.md
│   │   └── hello-world.en.md
│   ├── 红楼梦/                 # 书籍章节
│   │   ├── index.md
│   │   ├── 第001回.md
│   │   └── ...
│   └── images/                # 站点图片
│       ├── favicon.ico
│       ├── logo.png
│       ├── mobile_icon.png
│       └── title.png
├── overrides/                 # 主题覆盖文件
│   └── partials/comments.html # Giscus 评论组件
├── tools/                     # 辅助脚本
├── mkdocs.yml                 # 站点配置与导航
├── requirements.txt           # 构建依赖
└── .github/workflows/ci.yml   # 自动部署工作流
```

### 文件命名约定

- 中文页面直接使用中文文件名，例如 `Docker入门.md`。
- 英文版本与中文页面同名，加 `.en` 后缀，例如 `Docker入门.en.md`。
- 尽量避免空格和特殊符号；文件名会成为 URL 的一部分。
- **大小写很重要**：Windows 本地不区分大小写，但 GitHub Actions 的 Linux 环境区分，`Nav.md` 和 `nav.md` 是两个文件。

## 2. 新建文档

### 2.1 最简单的流程

以新建一篇《Docker 入门》为例：

**第一步：创建文件**

在 `docs/posts/` 下新建 `docker-notes.md`：

```markdown
# Docker 入门

> 发布日期：2026-10-19

这里写正文。

## 第一节

内容……
```

**第二步：创建英文版本（可选）**

新建 `docs/posts/docker-notes.en.md`。如果暂时不写英文，可以跳过，英文站会自动回退显示中文内容。

**第三步：登记到导航**

打开 `mkdocs.yml`，在 `nav:` 下找到「文章」，加入一行：

```yaml
nav:
  - 首页: "index.md"
  - 文章:
      - 我的第一篇文章: "posts/hello-world.md"
      - Docker 入门: "posts/docker-notes.md"
  - 关于: "about.md"
```

注意缩进：`文章` 下的一级子项是 6 个空格，不能混用 Tab。

**第四步：本地预览**

```bash
mkdocs serve
```

打开 `http://127.0.0.1:8000/My-Blog/`，确认页面和导航都正常。

### 2.2 放在哪里

推荐按主题分目录，便于长期维护：

```text
docs/
├── posts/              # 随笔、技术文章
│   ├── docker-notes.md
│   └── git-notes.md
├── notes/              # 学习笔记
└── projects/           # 项目记录
```

目录层级越浅越好；只有内容明显属于同一主题时再建子目录。

### 2.3 可以直接复制模板

根目录保留了写作模板：

- `template.md`：中文模板
- `template.en.md`：英文模板

复制一份到 `docs/` 下再修改即可。

### 2.4 常用 Markdown 写法

本主题已启用 `admonition`、`footnotes`、`attr_list`、`md_in_html` 扩展。

**提示框：**

```markdown
!!! note "提示"
    这是一条提示。

!!! warning "注意"
    这是一条警告。
```

**脚注：**

```markdown
这是一句话[^1]。

[^1]: 这是脚注内容。
```

**代码块：**

````markdown
```python
print("hello")
```
````

**图片：**

```markdown
![图片说明](../images/example.png)
```

**表格：**

```markdown
| 项目 | 说明 |
| --- | --- |
| 主题 | MkDocs Material |
```

### 2.5 新文档没有出现在导航里？

- 检查 `mkdocs.yml` 中是否加了对应的 `nav` 条目。
- 检查路径是否相对于 `docs/` 目录。
- 检查缩进是否为 2 的倍数。
- 未登记进 `nav` 的页面仍会生成，但不会出现在侧边栏。

## 3. 删除文档

删除一篇文章需要同时处理「文件」和「导航」两处，否则构建可能报错或留下死链。

### 3.1 操作步骤

**第一步：删除文件**

用资源管理器或命令删除：

```bash
git rm docs/posts/docker-notes.md
git rm docs/posts/docker-notes.en.md
```

如果整个目录都要删除：

```bash
git rm -r docs/posts/old-folder
```

**第二步：删除导航条目**

在 `mkdocs.yml` 的 `nav:` 中删掉对应行。如果删除后某个分组变空，也要把分组本身删掉：

```yaml
  - 文章:
      - Docker 入门: "posts/docker-notes.md"   # 删除这一行
```

**第三步：检查站内引用**

用编辑器的全局搜索，或执行：

```powershell
Get-ChildItem docs -Recurse -Filter *.md | Select-String "docker-notes"
```

把其他文章中指向该页面的链接一并删除或改到新地址。

**第四步：重新构建**

```bash
mkdocs build
```

确认没有「文件不存在」或「页面未加入 nav」之类的报错。

### 3.2 误删了怎么办

只要还没提交，可以恢复：

```bash
git checkout -- docs/posts/docker-notes.md
```

已经提交但想找回旧版本：

```bash
git log --oneline -- docs/posts/docker-notes.md
git checkout <commit-hash> -- docs/posts/docker-notes.md
```

### 3.3 删除时的注意事项

- 只删 `.md` 文件，不要顺手删掉 `docs/images/`。
- 删除页面后，其 URL 会 404；如果外部有人引用，建议保留一个内容为「文章已迁移」的占位页。
- 删除后一定要删 `nav` 条目，否则 `mkdocs build --strict` 会失败。

## 4. 调整目录与导航

导航完全由 `mkdocs.yml` 的 `nav:` 决定，**不取决于文件夹结构**。文件夹用于组织文件，`nav` 用于决定显示顺序和层级。

### 4.1 基本结构

```yaml
nav:
  - 首页: "index.md"
  - 文章:
      - 我的第一篇文章: "posts/hello-world.md"
      - Docker 入门: "posts/docker-notes.md"
  - 随笔:
      - 生活记录: "posts/life.md"
  - 关于: "about.md"
```

- 每一级子项相对于上一级增加 2 个空格。
- 冒号前是显示名称，冒号后是相对于 `docs/` 的路径。
- 显示名称里如果含有冒号、引号等特殊字符，用双引号包起来。

### 4.2 调整顺序

直接上下移动 `nav` 中的行即可，侧边栏顺序会同步变化。

```yaml
nav:
  - 首页: "index.md"
  - 红楼梦:
      - 目录: "红楼梦/index.md"
  - 文章:
      - 我的第一篇文章: "posts/hello-world.md"
```

### 4.3 增加多级目录

```yaml
  - 学习笔记:
      - 编程语言:
          - Python 笔记: "notes/python.md"
          - Rust 笔记: "notes/rust.md"
      - 工具:
          - Git 笔记: "notes/git.md"
```

对应的文件路径分别是 `docs/notes/python.md`、`docs/notes/rust.md`、`docs/notes/git.md`。

### 4.4 重命名文件或目录

**同时修改两处：**

1. 重命名磁盘上的文件；
2. 修改 `mkdocs.yml` 中对应的路径。

```bash
git mv docs/posts/docker-notes.md docs/posts/docker.md
```

然后同步修改 nav：

```yaml
      - Docker 入门: "posts/docker.md"
```

如果文件名里带 `.en`，英文版路径也要一起改。

### 4.5 英文导航

英文站的导航文字由 `i18n` 插件的 `nav_translations` 控制。新增一级栏目后，建议补一条翻译：

```yaml
plugins:
  - i18n:
      languages:
        - locale: zh
          default: true
          name: 简体中文
          build: true
        - locale: en
          name: English
          build: true
          site_name: Tao Wang's Blog
          nav_translations:
            首页: Home
            文章: Posts
            关于: About
            红楼梦: Dream of the Red Chamber
            使用说明: Guide
```

没有写翻译的栏目会保留中文，不影响构建。

### 4.6 常见导航错误

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 构建报 `The following pages exist in the docs directory, but are not included in the "nav"` | 页面未登记 | 加到 `nav` 或忽略该警告 |
| 构建报 `Nav entry ... not found` | 路径写错或文件不存在 | 核对文件名与大小写 |
| 侧边栏层级不对 | 缩进错误 | 每一级固定 2 个空格 |
| 本地正常、线上 404 | 大小写或中文路径编码 | 使用与线上一致的文件名，避免空格 |

## 5. 自定义站点信息

所有站点级设置都在 `mkdocs.yml` 顶部。

### 5.1 基本信息

```yaml
site_name: 王涛的博客
site_url: https://wangtaoknight.github.io/My-Blog/
site_author: TaoWang
site_description: 个人学习博客

repo_name: My-Blog
repo_url: https://github.com/wangtaoknight/My-Blog/

copyright: Copyright &copy; 2021-present <a href="https://github.com/wangtaoknight" target="_blank">wangtaoknight</a>
```

| 配置 | 作用 |
| --- | --- |
| `site_name` | 浏览器标题和页头显示的名称 |
| `site_url` | 线上完整地址，**末尾要带 `/`**，影响搜索与 sitemap |
| `site_author` | 作者信息 |
| `site_description` | 站点描述，用于搜索引擎 |
| `repo_name` | 右上角仓库按钮显示的文字 |
| `repo_url` | 点击仓库按钮跳转的地址 |
| `copyright` | 页脚版权信息 |

> 如果以后绑定自定义域名，需要同时修改 `site_url`，并在 `docs/` 下新增 `CNAME` 文件，内容为你的域名。

### 5.2 主题外观

```yaml
theme:
  name: material
  language: zh
  logo: images/logo.png
  favicon: images/favicon.ico

  palette:
    - media: "(prefers-color-scheme: light)"
      scheme: default
      primary: light blue
      accent: deep purple
    - media: "(prefers-color-scheme: dark)"
      scheme: slate
      primary: cyan
      accent: deep purple

  font:
    text: Roboto Slab
    code: Roboto Mono
```

- `primary` / `accent`：主色与强调色，可选值见 Material 官方文档（如 `blue`、`indigo`、`teal`、`red`）。
- `font.text` / `font.code`：正文字体与代码字体。
- `language: zh`：界面语言，影响搜索、目录等内置文案。
- `features`：控制导航行为，例如 `navigation.top`、`search.suggest`。

### 5.3 社交链接

```yaml
extra:
  social:
    - icon: fontawesome/brands/github
      link: https://github.com/wangtaoknight
```

可以添加多个，例如邮箱、知乎、B 站，图标名参考 Font Awesome。

### 5.4 访问统计

目前统计配置是注释状态。填入自己的 Google Analytics ID 后取消注释：

```yaml
extra:
  analytics:
    provider: google
    property: G-XXXXXXXXXX
```

不要继续使用原项目遗留的 ID。

### 5.5 评论

评论组件位于 `overrides/partials/comments.html`，默认整体注释关闭。启用步骤：

1. 在 GitHub 仓库 `Settings → General → Features` 勾选 `Discussions`；
2. 打开 <https://giscus.app/zh-CN>，填入仓库 `wangtaoknight/My-Blog`；
3. 安装 giscus App 并选择一个 Discussion 分类；
4. 把生成的 `data-repo-id`、`data-category-id` 填进文件；
5. 删除文件开头和结尾的 `<!--`、`-->` 注释标记。

### 5.6 搜索语言

```yaml
plugins:
  - search:
      lang:
        - zh
        - en
```

只写中文站时可以删掉 `en`。

## 6. 更换图片

站点图片都在 `docs/images/`，**保持文件名不变直接覆盖**即可，无需改配置。

| 文件 | 用途 | 建议尺寸 / 格式 |
| --- | --- | --- |
| `favicon.ico` | 浏览器标签页图标 | 32×32 或 64×64，`.ico` |
| `logo.png` | 页头 Logo（`theme.logo`） | 512×512，透明背景 `.png` |
| `mobile_icon.png` | iOS 添加到主屏幕图标 | 180×180，`.png` |
| `title.png` | 首页配图 | 1200×600 左右，`.png` |
| `sponsor.png` | 备用图片 | 按需 |

### 6.1 操作步骤

1. 准备好新图片，尺寸与格式尽量与上表一致；
2. 用同名文件覆盖 `docs/images/` 下的旧文件；
3. 本地运行 `mkdocs serve` 查看效果；
4. 如果没变化，按 `Ctrl + F5` 强制刷新，或重启预览服务。

### 6.2 修改 Logo

如果 `theme.logo` 未配置，在 `mkdocs.yml` 的 `theme:` 下加入：

```yaml
theme:
  logo: images/logo.png
```

### 6.3 文章中插入图片

推荐把文章配图放在文章同级目录或 `docs/images/`：

```markdown
![截图](../images/screenshot.png)
```

路径相对于当前 Markdown 文件。构建后图片会被复制到 `site/` 对应位置。

## 7. 写作与发布流程

### 7.1 本地预览

```bash
mkdocs serve
```

访问 `http://127.0.0.1:8000/My-Blog/`。修改文件后会自动重新构建。

只检查构建是否成功：

```bash
mkdocs build
```

产物在 `site/` 目录，已被 `.gitignore` 忽略。

### 7.2 提交与发布

```bash
git add -A
git commit -m "新增文章：Docker 入门"
git push origin rebuild-blog
```

当前 `.github/workflows/ci.yml` 只在推送到 `master` / `main` 时自动部署：

1. 把工作分支合并到 `master`；
2. 推送 `master`；
3. GitHub Actions 自动执行 `mkdocs gh-deploy`，推送到 `gh-pages` 分支；
4. 仓库 `Settings → Pages` 中确认 Source 为 `gh-pages`。

也可以在 Actions 页面手动运行 `ci` 工作流（已配置 `workflow_dispatch`）。

## 8. 常见问题

**改了文件但页面没变化？**

- 确认 `mkdocs serve` 仍在运行；
- 浏览器强制刷新（`Ctrl + F5`）；
- 检查是否改错了分支或目录。

**构建报“没有 git 日志”的警告？**

```text
WARNING - xxx.md has no git logs, revision date defaulting to today's date
```

这是 `git-revision-date` 插件对未提交文件的提示，提交后消失，可以忽略。

**中文文件名在线上打不开？**

浏览器会把中文转成百分号编码，这是正常的。不要使用空格、`#`、`?` 等字符，避免路径解析问题。

**英文站显示中文？**

缺少对应的 `.en.md` 文件时会自动回退到中文，属于预期行为。需要英文内容就补一份同名 `.en.md`。

**删除文章后构建失败？**

通常是 `nav` 里还留着已删除文件的路径，删掉对应条目即可。

**修改 `mkdocs.yml` 后构建报 YAML 错误？**

- 检查缩进是否统一为空格；
- 检查中文标签里是否有未转义的冒号，必要时加双引号；
- 检查 `nav` 每一项是否都是 `名称: "路径"` 的形式。

## 9. 快速检查清单

新增文章后，按顺序确认：

- [ ] 文件在 `docs/` 下，扩展名为 `.md`
- [ ] 英文版 `.en.md` 是否需要
- [ ] `mkdocs.yml` 的 `nav` 已登记
- [ ] 图片路径正确
- [ ] `mkdocs serve` 预览正常
- [ ] `mkdocs build` 无错误
- [ ] 提交并合并到 `master` 后，Actions 部署成功
